# LLM 观测方案对比报告：LangSmith、Langfuse 与自研 JSONL trace

## 核心结论

1. **成本**：在同等 trace 量级下，Langfuse 显著低于 LangSmith。以每月 50 万 trace、5 个用户为例，Langfuse Pro 为 $621，LangSmith Plus 为 $3,895，Langfuse 约便宜 6 倍；Langfuse 无席位费，LangSmith 对每个受邀席位收费 $39/月 [cite:1043]。LangSmith 采用"席位 + trace 用量 + LSU 计算单元"三重计费 [cite:1045]，Langfuse 云版按 unit 计费（$8/10 万 unit，量大递减至 $6/10 万），自托管版本免费且不限量 [cite:1042]。

2. **数据主权**：Langfuse 优势明显。Langfuse 为 MIT 许可，所有层级（含免费版）均支持自托管，包括气隙环境，自托管与云版本代码库一致 [cite:1053][cite:1056][cite:1057]；LangSmith 为专有平台，自托管仅限 Enterprise 层级，且其自托管 Engine 仍会将 trace 和代码内容发送至 LangChain 管理的推理服务 [cite:1053][cite:1056]。自研 JSONL 在数据主权上相对 LangSmith 托管模式有天然优势，相对 Langfuse 自托管则优势有限，主要差异在于不依赖第三方许可与治理政策变动 [cite:1057]。

3. **上手成本**：两者均较低且量级相近。LangSmith 多数团队可在一天内跑出首批 trace [cite:1037]；Langfuse 官方称"多数团队当天即可看到首批 trace"，自托管"可在几分钟内完成设置" [cite:1038][cite:1041]。两者均支持 OpenTelemetry 摄取，已有 OTEL 埋点的应用迁移成本较低 [cite:1037][cite:1038]。Langfuse 文档体系较完整，提供 Get Started、Core Concepts、SDK & API 参考、Troubleshooting & FAQ、Roadmap 等板块 [cite:1040]。

4. **自研 JSONL 方案**：现有证据材料未提供其完整实现成本（人力、基础设施、维护）的量化估算，也无法给出与商业方案的盈亏平衡规模 [unverified]。可确认的是：自研需自行承担 schema 设计与版本治理 [cite:1058]、查询/告警/评估能力的持续开发维护 [cite:1059][cite:1060]，以及存储与查询层的运维负担 [cite:1048]。

## 分述

### 一、成本对比

**LangSmith 定价模型**（三部分构成）[cite:1045]：
- 按席位收费：Developer 版 $0/seat/月（含 5k 基础 trace/月，超出按量付费）；Plus 版 $39/seat/月（含 10k 基础 trace/月，超出按量付费，可添加无限席位）；Enterprise 版定制价格。
- 按 trace 用量收费。
- 按 LSU（LangChain Standard Units）计费，$1.00/LSU，用于 Deployment、Fleet、Engine、Sandboxes、Tuned Evaluators 等服务计量。

**Langfuse 定价模型** [cite:1042]：
- 自托管版本免费且不限量。
- 云版本按 unit 计费，$8/10 万 unit，量大时单价递减至 $6/10 万，unit 涵盖 trace、观测、评分任意一种。

**同等量级成本差异** [cite:1043]：
- 每月 50 万 trace、5 个用户场景：Langfuse Pro 为 $621，LangSmith Plus 为 $3,895，Langfuse 约便宜 6 倍。
- Langfuse 无席位费；LangSmith 对每个受邀席位收费 $39/月。
- 数据保留：Langfuse Pro 保留 3 年历史数据，LangSmith SaaS 保留上限为 180 天（企业版亦然）[cite:1043]。

**托管 SaaS 参考价格基准** [cite:1047]：
- LangSmith：5 人团队、20 万 traces/月场景下月费接近 1200 美元（Plus 39 美元/人/月 + trace 超量计费）。
- Braintrust：基础版 249 美元/月（无限制用户，trace 超量另计）。
- Arize AX SaaS：50K traces/月档位约 50 美元/月，200K traces/月需定制企业合同。

### 二、数据主权对比

**数据存储位置** [cite:1053][cite:1056]：
- Langfuse：支持自托管，数据可存储于自有基础设施，且提供三个云区域。
- LangSmith：专有平台，自托管仅限 Enterprise 层级，且其自托管 Engine 仍会将 trace 和代码内容发送至 LangChain 管理的推理服务。

**数据保留策略** [cite:1053]：
- Langfuse Pro 保留 3 年历史数据。
- LangSmith SaaS 保留上限为 180 天（Enterprise 层级亦然）。

**自托管/私有化部署** [cite:1053][cite:1056][cite:1057]：
- Langfuse：MIT 许可，所有层级（含免费版）均支持自托管，包括气隙环境，自托管版本与云版本代码库一致；官方承诺保持开源与可自托管、无许可变更计划。
- LangSmith：专有平台，自托管是 Enterprise 专属附加项。

**合规认证** [cite:1052]：
- Langfuse Cloud：SOC 2 Type II、ISO 27001、GDPR、HIPAA。
- LangSmith Cloud：SOC 2 Type II、GDPR、HIPAA，未列出 ISO 27001。

**自研 JSONL 方案的数据主权** [cite:1057][cite:1059]：
- 相对 LangSmith 托管模式具有天然优势（数据完全自持）。
- 相对 Langfuse 自托管模式优势有限，主要差异在于不依赖第三方许可与治理政策变动。

### 三、上手成本对比

**接入步骤与典型上手时间**：
- LangSmith：多数团队可在一天内跑出首批 trace [cite:1037]。从 Langfuse 迁移到 LangSmith 通常需要一到两周，因 LangSmith 支持 OpenTelemetry 摄取，现有埋点无需修改即可沿用 [cite:1037]。
- Langfuse：官方 Get Started 流程为——注册账号或自托管、在项目设置中创建 API 凭证、按所选框架/SDK/OpenTelemetry 方式摄取第一条 trace；若应用已输出 OTEL span，可直接走 OpenTelemetry 指南 [cite:1040]。OpenAI SDK 是 OpenAI 客户端的 drop-in 替代，安装 `pip install langfuse` 并设置 LANGFUSE_SECRET_KEY / LANGFUSE_PUBLIC_KEY / LANGFUSE_BASE_URL 环境变量即可 [cite:1040]。官方中文页称自托管"可在几分钟内完成设置"，注册 Cloud 免费账户也只需几分钟 [cite:1041]。Langfuse 侧对比页称"多数团队当天即可看到首批 trace" [cite:1038]。

**SDK 集成复杂度** [cite:1037][cite:1038][cite:1040]：
- Langfuse：提供 OpenAI SDK（Python/JS-TS）、Vercel AI SDK、LangChain（Python/JS-TS）、Python SDK、JS/TS SDK、OpenTelemetry 等多种接入路径，支持 100+ 框架集成，不绑定任何单一 agent 框架。
- LangSmith：框架无关，既不要求 LangChain 也不要求 LangGraph，但可与两者协同工作。
- 两者均支持 OpenTelemetry 摄取，已有 OTEL 埋点的应用迁移成本较低。

**文档完善度** [cite:1040][cite:1041]：
- Langfuse：文档体系较完整，有 Get Started 指南、Core Concepts、SDK & API 参考、Troubleshooting & FAQ、Roadmap 等板块，并提供 Agent Skill 与 Docs MCP server（https://langfuse.com/api/mcp，无需认证）供编码 agent 查询最新文档；提供中文概述页（机器翻译），但明确说明网站其他资源仅提供英文。
- LangSmith：现有材料主要来自 LangChain 的对比营销页，未提供 LangSmith 自身文档结构的细节 [unverified]。

**厂商立场提示** [cite:1037][cite:1038]：Langfuse 对比页指出 LangSmith 部分能力（如 annotation queue 的路由/自动分配）"Not documented"；LangSmith 对比页称 Langfuse 的在线确定性评估"on the roadmap"、annotation queue 无路由规则文档、无生产告警功能。这些是双方互相指出的文档缺口，属厂商立场，需谨慎采信。

### 四、自研 JSONL trace 方案的成本与风险

**数据格式锁定风险** [cite:1058][cite:1059][cite:1061]：
- Langfuse 基于 OpenTelemetry 构建、框架无关。
- LangSmith 支持 OpenTelemetry 摄取，现有埋点可无需修改迁移，从 Langfuse 切换到 LangSmith 通常需一至两周，数据集可直接导出/导入。
- 自研 JSONL 若采用通用格式可降低锁定，但需自行承担 schema 设计与版本治理。

**查询能力风险** [cite:1059][cite:1060]：
- LangSmith 提供自动化规则、生产告警、在线确定性评估、注释队列路由与自动分配、自定义 RBAC 等能力。
- Langfuse 缺少生产告警、注释队列路由/分配逻辑，在线确定性评估仍在路线图中；其告警需通过 Metrics API 与集成实现。
- 自研 JSONL 方案需自行构建这些查询、告警与评估能力，存在明显功能缺口风险。

**长期维护成本** [cite:1048][cite:1058][cite:1059]：
- Langfuse 自托管可避免托管平台的基础设施与 schema 设计负担。
- 自研方案需自行承担 schema 治理、版本化规则与弃用计划，以及存储、查询与评估能力的持续开发维护。
- 自研/非标准组件的埋点需手动插桩，且需在跨服务场景传递 trace 上下文（trace id / prompt version）以保持事件可关联，并需通过端到端测试与 CI 断言防止埋点丢失。
- 若自研需自建存储与查询层，可参考 Langfuse 采用 ClickHouse 的运维负担：需规划磁盘 IO、分区策略、TTL、备份与恢复，高写入时需专门调优；长期保留全部 trace 时存储与查询成本随规模线性上升，需配合采样或压缩策略；团队缺乏 DB 运维经验时需谨慎规划或选择托管方案。

**轻量级替代路径** [cite:1048]：ELK/Datadog + 自定义事件模型可快速上手、成本与运维门槛较低，但缺乏 prompt 版本化、playground 跳转与内建评估流水线。

**自托管开源方案的隐形成本** [cite:1047]：Arize Phoenix、Langfuse 等软件本身免费，但需自行维护基础设施；若需横向扩展、高可用部署，需自建负载均衡与监控告警，对无专职 DevOps 的团队构成隐形成本。

## 未验证结论

以下结论无法被现有引用材料直接支撑，标注为 [unverified]：

1. 自研 JSONL trace 方案在数据主权上相对 LangSmith 和 Langfuse 的具体优势与风险，多为基于平台对比的间接推断，证据材料未直接讨论自研 JSONL 方案 [unverified]。
2. LangSmith 自身文档结构的细节，现有材料主要来自 LangChain 的对比营销页，未提供相关细节 [unverified]。
3. 自研 JSONL trace 方案从设计 schema、埋点、存储到可视化查询的完整实现成本（人力、基础设施、维护）的量化估算，以及其与 LangSmith/Langfuse 订阅或自托管成本相比的盈亏平衡规模阈值，现有材料未提供任何人力工时、存储单价或盈亏平衡点数据 [unverified]。
