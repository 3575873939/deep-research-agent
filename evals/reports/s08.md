# Chroma 持久化 API 版本差异调研报告

## 核心结论

1. **0.4.0 是持久化 API 的分水岭**：旧的 `chromadb.Client(Settings(chroma_db_impl='duckdb+parquet'))` 配置模式在 0.4.0 中已被移除，DuckDB 后端同时被移除，持久化改用 `PersistentClient(path='./chroma_db')`，底层改为 SQLite 存储 [cite:457]。0.4.0 之前的典型写法是 `chromadb.Client(Settings(chroma_db_impl='duckdb+parquet', persist_directory='.chroma/my-db'))` [cite:461]。

2. **当前版本的核心接口是 `PersistentClient`**：通过 `path` 参数指定磁盘存储目录，数据自动持久化并在启动时加载；不提供 `path` 时默认目录为 `.chroma` [cite:465][cite:467]。本地持久化模式使用 SQLite + 向量文件，适合单机开发、测试和小型生产环境 [cite:462]。

3. **用法层面变化有限但配置层面变化显著**：从教程描述看，使用持久化客户端时创建集合与读取已有集合都需使用 persistent client（而非旧版 dotclient），除客户端类型外其余操作（如 `create_collection`、`add`）保持不变 [cite:458]。而 v1.0.0 的破坏性变更主要集中在服务端/CLI/Docker 配置方式与若干 API 语义上 [cite:463]。

4. **"0.4 时代的 `Client(persist_directory=...)` 是否仍被支持"无法从现有证据证实**：官方迁移文档未声明移除 `chromadb.Client()` / `EphemeralClient()` / `PersistentClient()` 这些构造方式，但也未明确保留旧的 `persist_directory` 写法 [unverified]。

## 分述

### 一、0.4 时代的持久化 API

- **0.4.0 之前**：通过 `chromadb.Client(Settings(chroma_db_impl='duckdb+parquet', persist_directory='.chroma/my-db'))` 实现持久化，即用 `chroma_db_impl` 指定 duckdb+parquet 后端，用 `persist_directory` 指定磁盘路径 [cite:461]。
- **0.4.0**：上述配置模式被移除，不应再使用；持久化改用 `PersistentClient(path='./chroma_db')`，底层使用 SQLite，DuckDB 后端被移除 [cite:457]。

### 二、当前版本的持久化 API

- **核心接口**：`PersistentClient`，示例 `client = chromadb.PersistentClient(path="/path/to/save/to")` [cite:465]；`path` 指定数据库文件在磁盘上的存储位置，未提供时默认 `.chroma`，数据自动持久化并在启动时加载 [cite:459][cite:465]。
- **存储形态**：本地持久化模式将数据保存在本地磁盘（SQLite + 向量文件），适合单机开发、测试和小型生产环境 [cite:462]。
- **便捷方法**：客户端对象提供 `heartbeat()`（返回纳秒心跳，用于确认连接）和 `reset()`（清空并完全重置数据库，具有破坏性且不可逆）[cite:465]。
- **操作一致性**：使用持久化客户端时，创建集合和读取已有集合都需要使用 persistent client（而非旧版的 dotclient），除客户端类型外其余操作（如 `create_collection`、`add`）保持不变 [cite:458]。

### 三、0.4 到当前版本之间的破坏性变更与弃用项

按官方迁移文档时间线 [cite:463]（另见 [cite:453]）：

- **v1.0.0（2025-03-01）**：大量用 Rust 重写，性能显著提升。破坏性变更包括不再提供内置认证实现；`list_collections` 恢复为返回 Collection 对象 [cite:463]。进程内使用（`chromadb.Client()` / `EphemeralClient()` / `PersistentClient()`）时，新 Rust 实现会忽略 `chroma_server_nofile`、`chroma_server_thread_pool_size`、`chroma_memory_limit_bytes`、`chroma_segment_cache_policy` 等设置 [cite:463]。CLI 原先通过环境变量（如 `CHROMA_SERVER_CORS_ALLOW_ORIGINS`、`CHROMA_OTEL_COLLECTION_ENDPOINT`）提供的设置改为通过配置文件（`chroma run --config ./config.yaml`）提供 [cite:463]。Docker 同样改为配置文件方式，且容器内默认数据位置从 `/chroma/chroma` 改为 `/data`，挂载卷路径需相应调整 [cite:463]。
- **v0.6.0（2024-12-30）**：`list_collections` 由返回 Collection 对象列表改为仅返回集合名称，以避免自定义 embedding function 导致的错误；官方计划未来支持 embedding function 持久化 [cite:463]。同时放弃对 Python 3.8 的支持 [cite:463]。
- **v0.5.17（2024-10-30）**：不再支持为 metadata 过滤、ID 过滤等传入空列表或空字典（如 `where={}`）[cite:463]。
- **v0.5.12（2024-10-08）**：where 子句中的 `$ne`（不等于）和 `$nin`（不在其中）操作符语义更新——此前仅匹配包含指定键的记录，现在也会匹配不包含该键的记录 [cite:463]。

### 四、迁移注意事项

- v1.0.0 不再提供内置认证实现 [cite:453]。
- `list_collections` 恢复为返回 Collection 对象（此前 v0.6.0 起只返回集合名称，需配合 `get_collection` 与 `embedding_function` 使用）[cite:453]。
- CLI 与 Docker 场景下原先通过环境变量传入的配置改为通过配置文件提供；Docker 容器默认数据目录由 `/chroma/chroma` 变更为 `/data` [cite:453]。
- v0.5.17 起不再支持空列表/空字典作为 metadata 或 ID 过滤条件 [cite:453]。
- v0.5.12 起 where 子句中的 `$ne`、`$nin` 运算符语义变更，现在也会匹配不含该键的记录 [cite:453]。
- v0.6.0 起放弃对 Python 3.8 的支持 [cite:453]。
- LangChain 的 `langchain_chroma.Chroma` 集成（v1.1.0）构造函数中仍保留 `persist_directory` 参数 [cite:455]，但这属于第三方封装，不能直接证明 Chroma 核心库的持久化 API 现状 [unverified]。

## 未验证结论

- 关于 0.4 版本本身的持久化 API 变更，证据材料中未提供具体条目 [unverified]。
- 当前版本 PersistentClient 的完整方法签名在提供的材料中未完整展开 [unverified]。
- 0.4 时代 PersistentClient 的构造参数与方法签名，证据材料中未包含，无法进行具体对比 [unverified]。
- LangChain 的 Chroma 封装类构造函数包含 `persist_directory`、`client_settings`、`client` 等参数 [cite:460]，但这属于 LangChain 集成层，不能直接等同于 Chroma 原生 PersistentClient 的构造参数 [unverified]。
- 0.4 时代的持久化调用方式（如 `Client(persist_directory=...)`）在当前版本是否仍被支持，无法从现有证据中直接证实 [unverified]。
