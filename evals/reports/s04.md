# LangGraph 最新稳定版本 API 与 0.2 版本的 Breaking Changes 调研报告

## 核心结论

1. **无法确认"截至2025年5月"的最新稳定版本号**：现有证据中所有版本信息均晚于该时间点，包括 LangGraph 1.0 alpha（2025年9月2日）[cite:411]、1.0 正式版（2025年10月22日）[cite:409]，以及更晚的 langgraph==1.2.12 [cite:407]。因此本报告以证据中可确认的最新稳定版本（Python 参考文档标注 v1.2.12）为基准进行对比 [cite:410][cite:413]。

2. **官方 breaking changes 清单缺失**：在提供的证据材料中，唯一与 LangGraph 相关的发布说明类引用（citation 403）仅涉及 v1 新功能，未列出从 0.2 到最新稳定版本的 breaking changes 清单 [cite:403]。

3. **唯一可确认的破坏性变更**：`create_react_agent` 预构建组件已被弃用，取而代之的是 LangChain 的 `create_agent` [cite:403]。

4. **核心图构建 API 保持向后兼容**：StateGraph、add_node、add_edge、add_conditional_edges、set_entry_point、compile() 等 0.2 版本的核心 API 在最新版本中仍然存在且语义一致 [cite:400][cite:401][cite:402][cite:404][cite:410][cite:413]。

5. **新增能力（非破坏性）**：最新版本扩展了 StateGraph 构造函数签名（新增 context_schema、input_schema、output_schema）[cite:413]，新增 set_node_defaults 方法 [cite:413]，add_edge 支持起始节点列表 [cite:413]。

6. **checkpointer / interrupt / stream 的不兼容变更无法证实或证伪**：现有证据未提供明确的版本迁移或破坏性变更说明 [unverified]。

## 分述

### 一、版本号确认问题

针对"截至2025年5月 LangGraph 最新稳定版本号"这一子问题，无法从给定证据中确认。证据中提到的版本信息均晚于2025年5月：

- LangGraph 1.0 alpha 版本：2025年9月2日发布 [cite:411]
- LangGraph 1.0 正式版：2025年10月22日发布 [cite:409]
- GitHub Releases 页面显示 langgraph==1.2.12 等更晚版本 [cite:407]

因此，针对2025年5月这一时间点，没有可引用的版本号结论 [unverified]。

### 二、0.2 版本的核心 API 基线

LangGraph 0.2 版本中定义 StateGraph、节点和边的核心 API 包括：

- **StateGraph 类**：位于 `langgraph.graph` 模块，通过传入用户定义的状态 schema（如 TypedDict 或 Pydantic 模型）进行参数化 [cite:400][cite:402][cite:404]。
- **节点添加**：通过 `add_node` 方法添加，每个节点是接收当前状态并返回更新后状态的函数 [cite:400][cite:402][cite:404]。
- **边添加**：
  - `add_edge`：无条件边，直接跳转到下一个节点 [cite:400][cite:404]
  - `add_conditional_edges`：条件边，根据条件函数动态选择下一个节点 [cite:400][cite:404]
- **入口/出口控制**：`set_entry_point`（等价于 `add_edge(START, key)`）、`set_conditional_entry_point`、`set_finish_point` [cite:404]
- **序列添加**：`add_sequence` 按顺序添加节点序列 [cite:404]
- **编译**：图必须通过 `compile()` 方法编译后才能使用 [cite:402]

### 三、最新稳定版本的核心 API 变化

最新稳定版本（Python 参考文档标注 v1.2.12）中：

**StateGraph 类**：仍是核心类，用于定义基于共享状态的有向图工作流，节点通过读写共享状态通信，每个节点接收 State 并返回 Partial\<State\> [cite:410][cite:413]。

**构造函数签名扩展** [cite:413]：
```
StateGraph(state_schema, context_schema=None, *, input_schema=None, output_schema=None, **kwargs)
```
新增参数：
- `context_schema`：用于向节点暴露 user_id、db_conn 等不可变运行时上下文
- `input_schema` 和 `output_schema`

**节点 API** [cite:413]：
- `add_node` 仍用于添加节点
- 新增 `set_node_defaults` 方法，可为图中所有节点设置默认策略（如 retry_policy、timeout、cache_policy、error_handler），这些默认值在 `compile()` 时应用，且 retry_policy 和 timeout 默认值也适用于错误处理节点

**边 API** [cite:413]：
- `add_edge` 支持从单个起始节点或起始节点列表到目标节点的有向边；当提供多个起始节点时，图会等待所有起始节点完成后再执行目标节点
- `add_conditional_edges` 用于添加条件边 [cite:401][cite:413]
- 新增 `add_sequence` 方法，可按给定顺序添加并执行一系列节点

**入口/出口** [cite:401][cite:413]：
- `set_entry_point` 等价于 `add_edge(START, key)`
- `set_conditional_entry_point` 用于设置条件入口点
- `set_finish_point` 用于标记结束点

**编译**：图在使用前必须调用 `.compile()` 编译为可执行对象 [cite:401][cite:410]。

### 四、官方 breaking changes 清单

在提供的证据材料中，仅 citation 403 与 LangGraph 相关，且其内容为 LangGraph v1 的新功能说明，并未列出从 0.2 到最新稳定版本之间的 breaking changes 清单 [cite:403]。

该材料仅提及一项与破坏性变更相关的信息：

- **`create_react_agent` 预构建组件已被弃用**，取而代之的是 LangChain 的 `create_agent` [cite:403]。

除此之外，关于 0.2 到最新稳定版本之间的其他 breaking changes，证据材料中未提供任何官方文档或发布说明的支持内容 [unverified]。citation 405 和 406 与 LangGraph 无关，不能作为依据。

### 五、checkpointer / interrupt / stream 相关 API 的兼容性

现有证据只能部分回答该问题：

**1. interrupt API** [cite:399]
- 证据显示 `interrupt` 函数自 v0.2 起即存在（"Since v0.2"）
- 其签名与用法（在节点内调用、抛出 GraphInterrupt、配合 `Command(resume=...)` 恢复、需要 checkpointer）在文档中保持一致
- 未发现 0.2 到最新版本之间的不兼容变更说明

**2. checkpointer** [cite:399][cite:408]
- interrupt 依赖 checkpointer 持久化图状态
- 文档示例使用 `InMemorySaver`，并强调生产环境应使用持久化 checkpointer
- 未提供 0.2 与最新版本之间 checkpointer API 的兼容性对比

**3. stream** [cite:408][cite:412]
- 文档提到事件流式接口 `graph.stream_events(..., version="v3")`，interrupt 载荷通过 `stream.interrupts` 暴露，`stream.interrupted` 表示暂停
- 默认 `invoke()` API 下 interrupt 值位于 `__interrupt__` 键下
- JavaScript 侧 `INTERRUPT` 常量 `"__interrupt__"` 标注为 "Since v1.0"，暗示该常量在 1.0 才引入，可能与 0.2 时期的用法存在差异，但证据未明确说明这是否构成不兼容变更

**4. 核心结论**：关于 0.2 版本常用 API 是否发生不兼容变更这一核心问题，现有证据未提供明确的版本迁移/破坏性变更说明，无法证实或证伪 [unverified]。
