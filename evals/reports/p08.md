# sentence-transformers 的 BGE 系列与 M3E 系列中文嵌入模型在检索任务上的表现差异调研报告

## 核心结论

1. **检索性能上 BGE 系列整体优于 M3E 系列**：在 C-MTEB 检索子任务上，BGE (large) 得分为 71.53，明显高于 M3E (base) 的 56.91 和 M3E (large) 的 54.75 [cite:1228]；在另一组 C-MTEB 汇总口径下，bge-large-zh-v1.5 的 Retrieval 得分为 63.39，略高于 m3e-base 的 62.74（约 0.65 分）[cite:1232]。

2. **架构与训练策略差异是性能差距的主要来源**：BGE 基于 BERT 类结构，采用三阶段训练（RetroMAE 预训练 + 对比学习 + 指令微调），训练数据规模约 100M [cite:1219]；M3E 专注中文处理、部署灵活，但训练目标细节未公开 [cite:1217][unverified]。

3. **长文本处理能力差异显著**：bge-m3 支持最大 8192 token，而 bge-large-zh-v1.5 及 M3E 系列（具体参数未明确）通常为 512 token 级别 [cite:1212][cite:1213][cite:1216][unverified]。

4. **工程部署上 BGE 系列是当前更受推荐的选择**：m3e 系列自 2024 年起更新放缓，已被 BGE / Qwen3 赶超，新项目不再推荐作为首选 [cite:1220][cite:1223]。

5. **跨来源数值不宜直接比较**：不同来源的评测口径（数据集、指标定义、是否官方）可能不一致 [unverified]。

## 分述

### 一、官方评测指标对比（C-MTEB 检索子任务）

**BGE 系列：**
- BGE (large) 在 C-MTEB 基准上 Retrieval 子任务得分为 71.53，平均性能 63.96%，为当时所有中文向量模型中最高 [cite:1228]。
- BGE-Large-Zh 在检索任务上：Recall@1=0.756、Recall@5=0.843、Recall@10=0.892、NDCG@10=0.821 [cite:1227]。

**M3E 系列：**
- M3E (base) 的 Retrieval 子任务得分为 56.91，M3E (large) 为 54.75；平均性能分别为 57.79% 和 57.66% [cite:1228]。
- M3E 官方模型卡给出的 s2p 检索指标：m3e-large ndcg@10=0.7974，m3e-base ndcg@10=0.8004，m3e-small ndcg@10=0.7262 [cite:1229]。

**对比结论**：在 C-MTEB 检索子任务上，BGE (large) 的 71.53 明显高于 M3E (base) 的 56.91 和 M3E (large) 的 54.75 [cite:1228]。

> 注意：上述数值来自不同来源，评测口径可能不一致，跨来源数值不宜直接比较 [unverified]。

### 二、相同中文检索数据集上的具体差异

在 C-MTEB 中文检索基准上：

1. 从 C-MTEB 综合榜单看，m3e-base 的 Retrieval 子榜得分为 62.74，bge-large-zh-v1.5 为 63.39，bge-large-zh-v1.5 略高约 0.65 分 [cite:1232]。

2. 在另一组 C-MTEB 汇总数据中，bge-large-zh-v1.5 的 Retrieval 得分为 70.46；需注意 m3e-base 66.03、m3e-large 66.13 为综合 Avg 口径，非 Retrieval 口径，不能直接与 70.46 对比 [cite:1232]。

3. 关于 T2Retrieval、DuRetrieval、CmedqaRetrieval 三个具体数据集上 bge-large-zh-v1.5 与 m3e-base 的逐项 nDCG@10 差异，现有证据材料中未提供可直接对应的数值 [unverified]。

4. 定性结论：有技术文档指出 M3E（MokaAI）在 Retrieval 任务上整体落后 BGE 系列，且自 2024 年起更新放缓，新项目不再推荐作为首选，仅作为存量迁移对照基线 [cite:1233]。

5. bge-large-zh-v1.5 是中文 RAG 场景下风险最小的默认选择，稳定性经过广泛验证 [cite:1233]。

### 三、模型架构、训练数据与训练目标的差异

**模型架构：**
- BGE 系列基于 BERT 类结构，使用最后一层 CLS token 的 hidden state 作为 embedding，提供 small(24M)/base(102M)/large(326M) 三种规模 [cite:1219]；bge-m3 参数量 568M、向量维度 1024、最大长度 8192，支持 dense + sparse + multi-vector 三路输出 [cite:1220]。
- M3E 系列专注于中文文本处理，具备灵活的部署选项，适合资源受限或私有化场景 [cite:1217]。

**训练数据规模：**
- BGE 构建了 C-MTP（Chinese Massive Text Pairs），总量约 100M，其中 unlabeled 数据约 100M（来自 Wudao、知乎、百科等，用 Text2Vec-Chinese 过滤得分低于 0.43 的 pair），labeled 数据约 838K（来自 DuReader、mMARCO、NLI-Zh 等）[cite:1219]。
- bge-m3 训练集覆盖 100+ 种语言，包含语言内与跨语言语义匹配任务，并额外通过 GPT-3.5 合成 MultiLongDoc 长文档数据 [cite:1217][cite:1218]。
- M3E 训练语料覆盖电商、新闻、百科、法律等多领域 [cite:1220]。

**训练目标：**
- BGE 采用三阶段训练策略——pre-training（RetroMAE 重构目标，增强 retrieval 表现）、general-purpose fine-tuning（对比学习，in-batch negative，batch_size 达 19200）、task-specific fine-tuning（instruction-based fine-tuning 与 hard negative sampling）[cite:1219]。
- bge-m3 还引入自激励蒸馏，融合三种检索模式输出以提升单模式效果 [cite:1217]。
- M3E 的具体训练目标在现有材料中未详细展开 [unverified]。

**对检索表现的影响：**
- BGE 的 general-purpose fine-tuning 阶段后（BGE-i）整体表现已超过 OpenAI-Ada-002 和 M3E(large)，其中 retrieval 任务优势最大，这与其训练数据中包含大量 web content 的 (title, passage) 对密切相关 [cite:1219]。
- bge-m3 采用三种检索方式联合（ALL）时在三项评测中全面领先，其 dense 检索在多语言、跨语言检索中具有明显优势 [cite:1218]。
- M3E 自 2024 年起更新节奏放缓，已被 BGE / Qwen3 赶超，新项目不再推荐作为首选 [cite:1220]。

### 四、查询与文档长度的敏感度差异

**BGE 系列的长度特性：**
- bge-m3 支持最大输入长度为 8192 token，能够处理句子、段落、篇章、文档等不同粒度的输入文本 [cite:1212][cite:1213]。
- bge-m3 通过模型合成方式获取了大量文本长度分布多样化的训练数据，并改进了分批与缓存策略以支持长文本训练 [cite:1213]。
- bge-large-zh-v1.5、bge-base-zh-v1.5、bge-small-zh-v1.5 的最大长度均为 512 token [cite:1216]。
- 在长文档检索评测中，bge-m3 的稀疏检索效果显著高于稠密检索，说明关键词信息对长文档检索极为重要 [cite:1213]。
- bge-m3 通过预训练阶段就已获得出色的长文档检索能力，单纯使用稠密检索即可实现与 E5-mistral 相当的效果 [cite:1213]。

**M3E 系列的长度特性：**
- m3e 系列专注于中文文本处理，具有强大的文本处理能力和灵活的部署选项，适合资源受限或需要私有化的应用场景 [cite:1212]。
- m3e 采用 multi-domain 数据混合训练，训练语料覆盖电商、新闻、百科、法律等多领域，泛化均衡 [cite:1216]。
- 自 2024 年起 m3e 更新节奏放缓，被 BGE / Qwen3 赶超，新项目不再推荐作为首选 [cite:1216]。
- 关于 m3e 系列的具体最大序列长度参数，现有证据材料中未明确给出 [unverified]。

**对实际检索效果的影响：**
- 长文档被截断会导致关键段落丢失，是 RAG 系统中 Embedding 选型的关键风险之一 [cite:1216]。
- 在实际企业项目中，使用 bge-m3 替代 bge-large-zh-1.5 后，Token 输入长度从 512 增加到 8K，同时支持密集检索、稀疏检索和多向量检索 [cite:1215]。
- 对于约 200 字的短文章类 Knowledge Base 数据，保留文章完整性不切分，召回准确率从按段落切分的 55% 提升到 79% [cite:1215]。
- 结合 BM25 与向量检索的混合搜索以及 BGE Re-Ranker v2-M3 重排后，召回准确率进一步提升到 84%，多轮测试稳定在 85% 左右 [cite:1215]。
- 选型时需重点测试长文档首段偏置（截断 512/1024/8192 token 时召回率的下降幅度）以及查询-文档长度非对称（短 query 对长 doc 的匹配能力）[cite:1216]。

### 五、工程指标对比与部署选择

1. **向量维度**：bge-m3 和 bge-large-zh-v1.5 的向量维度均为 1024 [cite:1223][cite:1225]；bge-base-zh-v1.5 为 768，bge-small-zh-v1.5 为 384 [cite:1223]。m3e 系列的具体向量维度在现有证据中未提及 [unverified]。

2. **推理速度与显存占用**：bge-m3 参数量为 568M，推理较慢 [cite:1223]；bge-large-zh-v1.5 参数量为 326M，资源消耗较低，更适合资源有限的环境 [cite:1222][cite:1223]。m3e 系列被描述为"轻量级国产模型"，部署门槛低、推理快 [cite:1223]，但缺乏与 bge 系列的直接速度/显存对比数据 [unverified]。

3. **部署选择影响**：
   - 若项目主要处理中文文本且资源受限，bge-large-zh-v1.5 是更优选择，因其在中文场景下表现优异且资源消耗较低 [cite:1222]。
   - 若需处理多语言或长文本（最大 8192 token），bge-m3 更合适，但需接受其较高的推理开销 [cite:1222][cite:1223][cite:1224]。
   - m3e 系列自 2024 年起更新放缓，已被 BGE 等模型赶超，新项目不再推荐作为首选，仅作为存量迁移对照基线 [cite:1223]。
   - 在中文检索系统的部署选型中，bge 系列（尤其是 bge-large-zh-v1.5 和 bge-m3）是当前更受推荐的选择，m3e 系列因更新停滞和性能落后而逐渐退出主流选型 [cite:1223]。
