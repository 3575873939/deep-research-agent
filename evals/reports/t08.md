# Prompt Injection 攻击手法分类与间接注入防御难点调研报告

## 核心结论

1. **按注入位置划分，提示词注入主要分为直接注入与间接注入两类**：直接注入的威胁方向是"用户→开发者"，攻击者即用户本人；间接注入的威胁方向是"数据作者→用户"，用户本人并不知情，隐蔽性更强 [cite:822]。
2. **间接注入的典型载体包括网页内容、文档说明、代码注释、插件文档、README 文件、Markdown 文件等**，攻击路径是攻击者将恶意指令隐藏其中，Agent 读取时误将其视为合法指令并执行攻击代码 [cite:828][cite:829]。
3. **间接注入比直接注入更难防的核心原因**在于：信任边界模糊、内容来源不可控且暴露面近乎无边界、载荷不可预知且持续演化、多轮交互与递归注入等复合因素 [cite:818][cite:819][cite:820][cite:821]。
4. **业界主流共识是采用分层纵深防御**，组合多种概率性与确定性缓解措施，而非依赖单一防线；但提示注入在 LLM 架构底层难以彻底修复 [cite:832][cite:835]。
5. **间接注入已被证实为实际漏洞利用方式**，于 2023 年 5 月首次被正式认定为漏洞利用类型，几乎所有的 AI 应用都涉及三方数据，因此具有广泛的适应性 [cite:813]。

## 分述

### 一、攻击手法分类（按注入位置与意图）

**按注入位置划分**，提示词注入主要分为两类 [cite:822]：

- **直接注入（direct injection）**：用户的输入被模型误判为开发者指令，导致回应受到意外操控，是提示词注入最早出现的形式，威胁方向为"用户→开发者"，攻击者即使用模型的用户本人 [cite:822]。
- **间接注入（indirect injection）**：恶意提示并非来自用户当前输入，而是隐藏在外部数据源（如电子邮件、文档、网页）中，模型读取这些数据时可能将潜藏指令当作来自用户或开发者的指令执行，威胁方向为"数据作者→用户"，用户本人并不知情，隐蔽性更强 [cite:822]。

间接注入的常见场景包括：恶意网站将隐藏文本埋入网页导致 AI 总结结果被篡改、求职者在简历中嵌入白色字体隐藏内容使评分 AI 打出高分、教师在作文题目中插入隐藏提示使 AI 生成文本带上预设标记 [cite:822]。

在 AI Agent 架构中，用户输入和外部数据通常被直接纳入模型上下文，攻击者可通过构造特定指令诱导 Agent 执行原本不应触发的操作，例如仅通过聊天指令即可诱导 Agent 生成并执行高危系统命令；更复杂的间接注入则将恶意指令隐藏在网页内容、文档说明或代码注释中，如嵌入插件文档、README 文件或 Markdown 文件，导致 Agent 在初始化环境或安装依赖时执行攻击代码 [cite:825]。

**按混淆/隐藏手法划分**，存在"隐形提示注入（Invisible Prompt Injection）"，即使用看不见的 Unicode 字元（如 Unicode 标记字元，字码范围 E0000 至 E007F）来操弄提示，这些字元对使用者不可见但 LLM 仍会解读并回应，且可与其他提示注入技巧结合 [cite:826]。

**关于越狱与提示词注入的关系**：该术语由西蒙·威利森于 2022 年 9 月创造，他明确指出两者是不同技术——越狱旨在突破 AI 模型内置的安全护栏，而提示词注入则利用模型无法严格区分系统指令与用户输入这一根本弱点；尽管实际攻击中两者有时会被结合使用，但本质上有明确区别 [cite:822]。2023 年一篇论文提出了第二类提示注入——让非用户内容伪装成用户指令，论文作者凯·格雷沙克及其团队展示了对多款 AI 模型的成功攻击，受影响模型包括 GPT-4 和 Codex [cite:822]。

### 二、间接注入的典型载体与攻击路径

间接注入的典型载体包括：网页内容、文档说明、代码注释，以及插件文档、README 文件、Markdown 文件等 [cite:828][cite:829]。此外，市场数据、新闻、K 线注释中嵌入指令也被列为提示词注入的载体，用于操控 Agent 执行非预期操作 [cite:828][cite:829]。

攻击路径为：攻击者将恶意指令隐藏在这些载体中，当 Agent 在执行任务过程中读取这些内容时，可能误将其视为合法指令，从而执行攻击代码（例如在初始化环境或安装依赖时）[cite:828][cite:829]。该攻击模式的特点是不依赖传统漏洞，而是利用模型对上下文信息的信任机制来影响其行为逻辑 [cite:828][cite:829]。

### 三、间接注入为何比直接注入更难防

1. **信任边界模糊、模型无法区分指令与数据**：间接注入中，攻击者将恶意指令嵌入第三方内容（如邮件、文档、网站、插件），AI 会把恶意指令误当作合法命令执行；这一挑战因 AI 无法区分用户输入和外部内容而复杂化，使传统输入验证不足 [cite:818]。研究也确认，攻击成功的根本原因是 LLM 无法区分信息性上下文与可执行指令，且缺乏规避执行外部内容中指令的意识 [cite:819]。由于 LLM 在架构底层很难像传统编程语言那样稳定区分"指令"与"数据"，业界并不存在可普适消除提示注入风险的单一文本防线 [cite:820]。

2. **内容来源不可控、暴露面广**：生成式 AI 系统通常处理来自外部源的不受信任内容，如电子邮件、文档、网站和插件，这打开了间接提示注入的严重漏洞 [cite:818]。对浏览器代理而言，其有用性所依赖的普遍性也使风险更广泛——代理可能在实际上无边界的范围内遇到不受信任的指令，包括邮件与附件、日历邀请、共享文档、论坛、社交媒体帖子和任意网页 [cite:821]。

3. **防御者无法预知载荷、攻击面持续演变**：提示注入被视为长期的 AI 安全挑战，需要不断强化防御来应对，OpenAI 通过自动化发现新型提示注入攻击来暴露防御漏洞并推动修补，说明攻击策略持续演化、难以预先穷举 [cite:821]。攻击者还会使用高级混淆技术进行旁路绕过，如多语言与同形异义编码、渐进式洗脑（多轮攻击）、上下文溢界（Context Stuffing）等，仅靠静态正则或基础检测器无法测出真实防线的鲁棒程度 [cite:820]。

4. **多轮交互带来的风险**：渐进式洗脑式多轮攻击中，前三轮对话看似无害且迎合模型角色设定，但在累计建立足够多基于 Attention 的安全隐状态后，于后续某轮抛出隐蔽的恶意指令 [cite:820]。

5. **防御系统自身存在递归注入风险**：当防御系统本身使用 LLM 判定输入是否恶意时，攻击者可在载荷中嵌入针对检测模型的二次注入，形成"递归注入"；检测模型与被保护模型可能共享相似脆弱性，若检测层被绕过，后续所有防线可能级联失效 [cite:820]。

6. **能力越强反而越脆弱**：对 25 个 LLM 的评估显示，所有模型都对间接提示注入敏感；对于基于文本的攻击，能力更强的 LLM 表现出更高的脆弱性，GPT-4 和 GPT-3.5-turbo 攻击成功率相对较高，其卓越的指令遵循能力无意中使其更擅长执行恶意指令 [cite:819]。

综上，间接注入的防御难点在于信任边界模糊、外部内容来源不可控且暴露面近乎无边界、载荷不可预知且持续演化、多轮交互与递归注入等复合因素，因此需要采用分层纵深防御（提示防护、聚焦/内容隔离、计划偏移检测、批评者代理、信息流控制、最小特权、人机交互等）而非单一防线 [cite:818][cite:820]。

### 四、主流防御策略及其有效性

针对间接提示注入，业界主流共识是采用分层纵深防御（Defense-in-Depth），组合多种概率性与确定性缓解措施，而非依赖单一防线 [cite:832][cite:835]。主要策略包括：

1. **输入净化/提示防护（Prompt Shields）**：分析和清理传入提示以检测注入尝试 [cite:832]；
2. **内容隔离/聚焦（Spotlighting）**：使用数据标记和元处理隔离并消除外部内容，配合信息流控制（IFC）防止不受信任数据影响关键推理 [cite:832]；
3. **权限最小化**：仅授予代理完成任务所需的最短生存期权限，用完即删 [cite:832]；
4. **输出过滤/批评者代理**：实时审核输入和输出，尤其在多代理系统中 [cite:832]；
5. **人工确认（人机交互）**：作为最后一道防线，由用户验证有风险的操作 [cite:832]。

Google 针对 Gemini 也采用覆盖提示生命周期各阶段的分层策略，包括提示注入内容分类器、安全思维强化、Markdown 清理与可疑网址屏蔽、用户确认框架等 [cite:834]。

**有效性方面**：分层防御可显著降低成功攻击概率，即使一层被绕过，下游缓解也能限制损害范围 [cite:832]；但业界普遍认为提示注入在 LLM 架构底层难以彻底修复，不存在可普适消除风险的单一文本防线，防御核心在于组合对抗与降低影响半径 [cite:835]。

**权衡包括**：复杂性增加、性能开销（运行时监视或隔离推理可能带来延迟）、误报（概率性防御可能阻止合法操作）以及需要持续资源投入 [cite:832]。此外，使用 LLM 做检测器存在递归注入风险，检测层可能被二次注入绕过，需采用多模型集成、非 LLM 辅助检测、对抗训练和分层隔离等缓解手段 [cite:835]。

### 五、真实系统中的已知案例与漏洞报告

在真实系统中，间接提示词注入攻击（IPIA）已被证实为一种实际漏洞利用方式，于 2023 年 5 月首次被正式认定为漏洞利用类型 [cite:813]。

已知的具体案例包括：**Mavy GPT 日历泄露事件**，攻击者通过向 Google 日历发送恶意邀请，成功修改了受害者的日历事件并以其名义发送邮件，该案例中攻击者通过要求模型列出所有功能、数据源和系统提示词来探索攻击面，最终利用精心构造的注入提示实现了攻击 [cite:813]。

在 AI Agent 架构中，间接注入的典型方式是将恶意指令隐藏在网页内容、文档说明或代码注释中，例如在插件文档、README 文件或 Markdown 文件中嵌入恶意命令，导致 Agent 在初始化环境或安装依赖时执行攻击代码 [cite:816]。此外，插件与技能系统（Skills/MCP/Tools）的生态也正在成为新的供应链攻击入口 [cite:816]。

间接注入攻击的实施难度更大，但危害也更大，几乎所有的 AI 应用都涉及三方数据，因此这种攻击具有广泛的适应性 [cite:813]。
